# x402 Integration

LetAgentPay is a **non-custodial policy layer** for [x402](https://x402.org) HTTP 402 micropayments. Every x402 payment your agent signs runs through the same policy engine as a Stripe transaction — same budgets, same categories, same human approval.

> **TL;DR.** Agent receives `HTTP 402` → asks LetAgentPay for authorization → LetAgentPay checks policy → agent signs the tx with its own wallet and pays → agent reports the tx hash for audit. LetAgentPay never holds keys, never moves funds.

## Why combine LetAgentPay with x402

x402 by itself gives you on-chain micropayments. It does **not** give you:

- Daily / weekly / monthly caps that survive across requests
- Per-category spending rules
- Human-in-the-loop approval before a tx is signed
- Audit trail with reconciliation between authorized and actual amounts
- A kill switch when an agent loops

LetAgentPay adds those four checks **before** the wallet signs anything. The cap applies to all rails at once — x402, Stripe, and prepaid wallets all share one budget bucket.

## Architecture

```
1. Agent → GET resource → HTTP 402 + payment requirements
2. Agent → POST /api/v1/x402/authorize → LetAgentPay checks policy → authorized | declined
3. Agent → signs tx with its own wallet → pays merchant → gets resource
4. Agent → POST /api/v1/x402/report → tx_hash for audit + reconciliation
```

**What LetAgentPay does and does not do:**

| Does                                                            | Does not                                  |
| --------------------------------------------------------------- | ----------------------------------------- |
| Checks policy before authorization                              | Hold private keys                         |
| Approves / declines payments                                    | Move funds through its own account        |
| Logs and reconciles transactions                                | Custody wallets                           |
| Manages budgets and limits across rails                         | Sign transactions on behalf of the agent  |
| Can act as a non-custodial x402 facilitator (verify + relay)    | Convert fiat ↔ crypto                     |

## Features

- **Hard caps across rails.** A `daily_limit` of $100 applies whether the agent pays via x402, Stripe, or a prepaid wallet — they all decrement the same bucket.
- **Live exchange rates.** USDC ↔ USD conversion happens at authorization time (15-second cache TTL). Budgets stay in the user's currency.
- **Stablecoin de-peg protection.** Authorization is declined with `STABLECOIN_DEPEG` if the price drifts beyond the configured tolerance.
- **Chain and domain allow-lists.** Restrict which networks (Base, Solana, etc.) and recipient domains the agent can pay.
- **tx-hash dedup.** One on-chain transaction cannot close two authorizations. Replay protection out of the box.
- **Actual-amount reconciliation.** When the settled amount differs from the authorized amount, the budget is auto-corrected.
- **Same human approval flow.** Authorizations above the auto-approve threshold land on the live dashboard exactly like fiat requests.

## Quick start

### 1. Register a wallet (one-time)

```bash
curl -X POST https://api.letagentpay.com/api/v1/x402/wallets \
  -H "Authorization: Bearer agt_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "address": "0x1234...",
    "chain": "eip155:8453"
  }'
```

The wallet address is stored for reference only — LetAgentPay never holds the key.

### 2. Authorize a payment

```bash
curl -X POST https://api.letagentpay.com/api/v1/x402/authorize \
  -H "Authorization: Bearer agt_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "payment_requirements": {
      "scheme": "exact",
      "network": "eip155:8453",
      "amount": "10000",
      "asset": "USDC",
      "pay_to": "0xabcd...",
      "resource": "https://api.example.com/data"
    },
    "max_amount_usd": 0.05
  }'
```

Response:

```json
{
  "authorized": true,
  "authorization_id": "1c8f...",
  "expires_at": "2026-05-11T12:01:00Z",
  "remaining_daily_budget": 49.95,
  "remaining_monthly_budget": 499.95
}
```

### 3. Pay, then report the tx hash

```bash
curl -X POST https://api.letagentpay.com/api/v1/x402/report \
  -H "Authorization: Bearer agt_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "authorization_id": "1c8f...",
    "tx_hash": "0xdead...",
    "actual_amount_usd": 0.048
  }'
```

The reconciliation engine adjusts the daily/weekly/monthly buckets if `actual_amount_usd` differs from the authorized amount.

## Decline reasons

| Code                              | Meaning                                                          |
| --------------------------------- | ---------------------------------------------------------------- |
| `CHAIN_NOT_ALLOWED`               | Network is not in the agent's allow-list                         |
| `DOMAIN_BLOCKED`                  | Recipient or resource domain is explicitly blocked               |
| `DOMAIN_NOT_ALLOWED`              | Recipient domain is not in the allow-list                        |
| `AMOUNT_EXCEEDS_PER_REQUEST_LIMIT`| Single payment is larger than the per-request cap                |
| `DAILY_BUDGET_EXCEEDED`           | Today's spending plus this request exceeds the daily cap         |
| `WEEKLY_BUDGET_EXCEEDED`          | This week's spending plus this request exceeds the weekly cap    |
| `MONTHLY_BUDGET_EXCEEDED`         | This month's spending plus this request exceeds the monthly cap  |
| `BUDGET_EXCEEDED`                 | Total agent budget exhausted                                     |
| `STABLECOIN_DEPEG`                | USDC price drifted outside the configured tolerance              |
